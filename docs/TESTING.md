# 测试指南

## 自动化测试

```bash
npm test          # 仅单元 / 构建测试
npm run verify    # lint + format:check + test + build
```

当前覆盖：

- `tests/unit/manifests.test.mjs`：生成的 MV3 清单、版本一致性、content script 顺序、资源映射、Chrome / Firefox 差异
- `tests/unit/locales.test.mjs`：中英文键集合、空文案、占位符一致性、运行时文案与 `_locales` 一致
- `tests/unit/defaults.test.mjs`：归一化（零宽 / 全角）、关键字与正则匹配、非法输入、默认规则结构与代表性密钥检测
- `tests/unit/lang.test.mjs`：语言变体归一化、`zh-CN` 选择、`data-i18n-html` 渲染
- `tests/unit/background.test.mjs`：Chrome / Firefox 启动时复用共享默认值并初始化存储
- `tests/unit/settings.test.mjs`：导入配置的字段、规则、正则与站点校验
- `tests/unit/build.test.mjs`：构建两个浏览器包，校验产物文件、清单与生成的 `lang.js`

测试使用 Node 内置 `node:test`，不引入测试框架。新增纯逻辑时必须补测试，优先覆盖边界与抗变形场景。

## 手动冒烟

涉及 DOM、站点适配、发送拦截与 i18n 的改动，至少在一个 Chromium 浏览器完成下表；发布前需覆盖 Chrome + Firefox。手动测试前先运行 `npm run build`，并加载 `dist/chrome` 或 `dist/firefox`。

### 基础功能

| 场景         | 步骤                                         | 预期                                  |
| ------------ | -------------------------------------------- | ------------------------------------- |
| 关键字命中   | 输入包含已启用关键字规则的文本               | 命中片段高亮，警告条出现              |
| 正则命中     | 输入 `sk-` + 20 位以上字符                   | 命中 OpenAI Key 规则                  |
| 禁用规则     | 关闭某条规则后输入对应文本                   | 不再命中                              |
| 抗变形       | 在敏感词中插入零宽字符或使用全角字母         | 仍能命中，高亮覆盖原始片段            |
| `warn` 级别  | 输入 `password=test123`（默认 warn）         | 高亮 + 警告，但允许发送               |
| `error` 级别 | 输入伪造的 `sk-` 密钥                        | 高亮 + 警告，Enter 与发送按钮均被拦截 |
| 粘贴扫描     | 粘贴包含敏感内容的文本                       | 与键入一致触发扫描                    |
| 清空输入     | 清空输入框                                   | 高亮与警告条消失                      |
| 警告条悬停   | 鼠标移入警告条                               | 警告条在顶部 / 底部之间切换           |
| SPA 跳转     | 在 ChatGPT / Claude 中切换会话或使用站内导航 | 旧警告条消失，新输入框可正常检测      |
| 中文输入法   | 使用拼音输入并回车选词                       | 选词回车不被当作发送拦截              |
| SVG 发送按钮 | 在 SVG 图标按钮站点输入 `error` 级内容并点击 | 点击被拦截，控制台无异常              |
| 语言检测     | 浏览器语言设为 `zh-CN` 后首次安装            | 界面为中文                            |

### 配置页

| 场景       | 步骤                                         | 预期                                |
| ---------- | -------------------------------------------- | ----------------------------------- |
| 保存规则   | 修改规则描述 / 级别后刷新页面                | 修改已持久化                        |
| 恢复默认   | 点击「恢复默认」并确认                       | 规则恢复为内置默认                  |
| 导出       | 点击「导出」                                 | 下载包含 `rules` 与 `sites` 的 JSON |
| 导入合法   | 导入导出的 JSON                              | 规则与站点被替换，界面刷新          |
| 导入非法   | 导入缺少 `rules` 数组的 JSON                 | 提示格式错误，现有配置不被破坏      |
| 非法正则   | 导入含 `type: "regex", pattern: "["` 的 JSON | 提示对应规则正则无效，配置不变      |
| 连续编辑   | 快速修改规则描述后等待约 1 秒                | 只出现一次保存提示，刷新后保留      |
| 规则测试   | 在测试面板输入样例                           | 实时高亮并显示拦截 / 警告计数       |
| 自定义站点 | 添加 `*.example.com` 与选择器并保存          | 目标站点生效，其他站点不受影响      |
| 语言切换   | 切换到 English 后刷新                        | 界面保持英文，选择已持久化          |

### 弹窗与同步

| 场景       | 步骤                               | 预期                           |
| ---------- | ---------------------------------- | ------------------------------ |
| 总开关     | 关闭「启用检测」                   | 已打开标签页立即停止检测       |
| 子开关     | 关闭「高亮 + 警告条」              | 不再显示视觉警告，拦截仍生效   |
| 拦截开关   | 关闭「拦截发送」                   | `error` 级别只提醒，不阻止发送 |
| 多标签同步 | 在两个标签页打开同一站点并修改配置 | 两个标签页均更新               |

### 隐私与兼容性

- 打开 DevTools → Network，操作输入与配置：**不应出现任何扩展发起的请求**
- 在 Chrome 与 Firefox 各执行一次基础功能与配置页用例
- Firefox 重点检查：配置同步、发送拦截、语言切换、`chrome.*` 回调兼容性
- 检查扩展页面 Console 与 Service Worker Console 无未捕获异常
